# Wheeled cargo trolley

Install `import { installCargo13 } from './cargo13.js'`; `this.useModule('cargo13', installCargo13)`.

A real 3D wheeled basket/cart spawns beside the ship (x7.7,z7), on standard moons, Algorithm HQ and the Relay Dock. E on the yellow handles claims/releases driving. Walk and turn to steer the cart in front of you; it follows on the host at a maximum 3.8 m/s, slower with load. It does not teleport with the player. Wall rays sample both sides at two heights; downward ground rays reject cliffs, steep slopes and large height changes. Cart basket has a real Rapier obstacle collider replicated on peers.

Stop/release the handles to load: E toward basket front loads the item in your hand, or the closest eligible loose item within 2.5m. E on right side unloads one; E on left side unloads all. Eight capacity units, total weight 120. A stationary big prop costs four capacity units: vases, amphorae and aquariums can be loaded when weight fits. Active beam ownership must first be released. Bodies, soulbound/stashed items, deployed ladders and power apparatus cannot load. No new keyboard binding; C remains crouch.

While driving, normal entrance/fire-exit E prompts become “Take trolley through doorway”. This uses a host request instead of the local player-only portal. Host checks driver identity and both player/cart distances to the actual indexed map entrance. The destination is derived exclusively from the corresponding map spawn and floor/wall checked. Existing loaded IDs stay in custody. Cart and driver transfer together; a short host transition grace covers remote position packet latency. No client coordinate can request an arbitrary teleport.

Host validates distance, living requester, cart occupancy, item custody/owner and capacity. Existing item identities, values and special state remain intact: load broadcasts the standard `it held` event with reserved creature-style custody `c:cargo13`; unload broadcasts standard `it drop`. This blocks ordinary pickup/drop/grab requests while stored and clears the original holder's inventory. Stored originals visibly occupy the basket, scaled to fit; dropping restores scale. No duplicate item spawn or copied value. Active physics beam ownership is rejected to avoid races.

`run.cargo13` contains map, transform, driver and loaded ids. It travels in existing welcome/run snapshots and host migration. Host transform packet `cg13state` is host-only and capped at 10Hz while driving. Full run synchronization only on state transitions. Driver disconnect/death/distance jump clears the handles. Takeoff and map unload first release every item back into world; if cart is aboard, drops stay aboard for existing tally/save logic. Cargo outside ship follows ordinary outside-scrap takeoff rules: bring the cart aboard or unload and carry cargo inside before departure. Map unload never removes the item itself through this module.

One focused test: `node tools/harness/cargo13.test.mjs` covers capacity/weight, ghost custody, other peer ownership, beam race rejection exactly-once unload, stationary big props, beam ownership, and doorway driver/distance validation. Syntax checks passed. Browser physical handling/late join/host migration await lead QA. Cart uses a conservative flat orientation; no wheel suspension, stairs climbing or collision-based pushing by a second player. These are future polish, not inventory panel substitutes.
