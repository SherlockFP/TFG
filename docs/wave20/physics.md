# Native manual cargo push

The existing cargo trolley retains its custody/capacity/route rules and LMB beam remains available. The new contextual action uses the existing interaction key on nearby loose heavy salvage: **Grab [LMB] · Push [E]** (actual remapped key shown, EN/TR/RU). A short 0.3-second manual push applies native Rapier impulses to the existing item body. It does not teleport cargo, take ownership, create/drop copies, add rewards, introduce another physics ledger or add a key.

Host requests carry only native item ID, current map/phase token and monotonic request number. The host derives force direction from the actual actor look. Known alive/non-downed actor, current map, free hands, range, aim and static/door LOS are checked. Custody excludes held, owned, carried, bagged, selling, deployed ladder, player body and apparatus. Each physics boundary rechecks validity; walking away, turning away, grabbing, holding, sale or map changes stop subsequent impulses. One burst per body plus peer/body cooldowns and a 2.5m/s horizontal speed ceiling prevent stacked pushes. The body retains real gravity, collisions, friction and its original mass.

The original tiny point impulse was measured first: mass8 vase moved 0.0023m with delta-speed0.55/max-impulse12; initial tuning1.6/55 alone moved0.0104m. These were too small to present as useful interaction. The approved short burst combines initial1.6 delta speed with bounded fixed-step impulses corresponding to12m/s², each capped55. Installed native Rapier evidence: vase body mass8 (carryweight30) moves0.5824m; server body mass55 (carryweight150) moves0.7527m over0.5s with sampled maximum2.166m/s. This is a controlled ground fixture, not universal movement distance across every material/shape.

`cargo20.test.mjs` drives actual installed contextual E→registered host handler, native WorldItem bodies/real floor and wall, native item snapshots to a second peer, forgery/replay/rate limits, held/owner/static/free-hand/LOS/map rejection, speed caps and next-boundary cancellation. Existing ItemManager impact detection does not trigger the server's fragile-damage threshold during the measured push. Value/custody/ID are unchanged; the existing snapshot path mirrors physical position. No alternative peer event carries transforms or force.

`cargo20_core.js` exposes `looseCargo` and `impulseCargo` for the new creature's separately host-validated nearby prop interaction. The helper retains gentle point-impulse defaults; only the player module schedules short bursts. No creatures, actions, item-manager or camera source was edited by this lane.

Serialized browser QA confirmed native E pushing of one real vase (~0.55m), mirrored native host/peer position within snapshot quantisation, unchanged value100, null holder/owner and one original ID; native LMB then grabbed that same item. See PLAYTEST for setup boundaries. Integration: installCargo20 after native interaction wrappers are installed; Game installer belongs to root. No performance/FPS claim is inferred from this physical fixture.
