# Wave 6 - ZONES 2 (zones v2; extends module `zones`, MASTERPLAN §26)

v1 (docs/wave5/zones.md) had five gaps: facility wings were outdoor "annex relays", ring defences skipped placement validation, no wall pieces, no extractors, generated-sector zones went dormant when the sector rotated, raiders walked straight lines, no ship map.
v2 closes all five inside the same module (`this.useModule('zones', installZones)`; `config.zones = false` still turns everything off). No new game module and no shared-file edit beyond `src/game/horror_core.js` (`straightAxis` is now exported).
Another agent ("unify") is building `defense_core.js`: nothing here creates it or competes with it. The adapter surface is small on purpose: `Q.checkSpot` / `Q.validateWall` take plain callbacks (`solid`, `obstacles`, `circles`) and `zones2.js` `placeRing` / `raiderStep` / `liveBegin` are the only places that touch deployables / siege state.

## Files
- `src/game/zones2_core.js` pure rules: interior partition + trap planner / validator, wall + ring-spot validation, raider flow + movement, archive. Node-tested.
- `src/game/zones2.js` runtime installed BY `zones.js` (`installZones2(X)`): interior traps (host state machine + client views), wall pieces (instanced view + colliders), validated ring placer, extractor + wall requests, raider AI, upkeep ammo, archive sync, ship CRT. `src/game/zones_core.js` gained the numbers (trap defences, `WALL`, `MINER`, `incomeRows`, ammo fraction). `src/ui/panels/zones.js` gained WALLS / EXTRACTOR / trap sections and the shared `drawSectorMap`. Strings: `zones_i18n.js` (TR + RU).
- Tests: `node tools/harness/zones2.test.mjs [layouts=90]` (143k checks: pure rules), `node tools/harness/zones2_host.test.mjs` (120 checks: the real installer against a mock game), plus the unchanged `zones.test.mjs` (1088) and `zones_host.test.mjs` (28), `horror.test.mjs` / `horror_build.test.mjs` / `horror_install.test.mjs`. Browser: `tools/harness/wave6_zones2.js`.

## 1. Interior zones (facility wings are real zones)
- **Partition** (`partitionWings`): the walkable part of the layout (the horror `reachableCells`: no vaults, containment, arena, locked doors) is split by multi-source BFS from the entrance and the fire exits; every reachable cell belongs to exactly one wing (tested on 90 layouts x 6 themes). Wing names come from `zoneSpec` (`entrance`, `fire0`, `fire1`), so zone ids / threat / unlocks are unchanged.
- **Core** inside the wing: an ordinary room (never vault / generator / core / treasure / arena / maze), 3-9 cells from the wing anchor, cores >= 4 cells apart; last resorts: any hallway cell, then the lobby. A wing that the crew cannot reach without a key (a few mansion layouts: 9 free cells) keeps the v1 outdoor annex relay, so no zone is ever lost.
- **Capture** is the same rule: 20 s without a hostile within 28 m, hold E for 4 s. The scan / prompt / plant only count people on the same level (interior relays are at facility height; standing on the terrain above does nothing).
- **Interior fortify**: the FORTIFY list of a wing shows the five horror trap types as defences (`t_spikes`, `t_crusher`, `t_electric`, `t_flame`, `t_laser`; cost ~2.2x the pay-to-arm price, upkeep 2-5, power 8-15, laser / flame / live floor from quota 2). They occupy the normal defence slots. Placement = the horror planner: `findRuns` straight hallway runs, no doorway, wing + reachable, off the core, no overlap with other zone traps (>= 3 cells apart), off the horror plan's pay-to-arm traps + panels, off built-in laser grids; the planner prefers the runs most raider walks pass through (chokepoint map = `flowLoad`; the first trap of a wing sits on a route most raiders use in about three quarters of wings).
- **Behaviour**: permanently armed while the zone is paid for (dry upkeep = idle), telegraph -> strike exactly like horror (same `stepTrap`, damage, `TrapView`), creatures only: the crew is never hurt by its own traps. Positions are re-planned at every landing from the stored counts (`st.d`), the host broadcasts the lane list (`znx tp`) and states (`znx ts`); clients only build views.
- **Live defence in a wing**: raiders (`sg_*`, `zone: 'in'`) spawn 7-16 cells from the core and walk a cell flow field (`coreDist` / `flowTarget`, doors opened with `openDoorsNear`) to the core, through the trap lanes.

## 2. Outdoor placement: walls, gates, validated ring
- **Pieces** (homeworld2 style): snap grid of 1.5 m fine cells, a piece is 3 m x 0.5 m x 2.2 m, rotation 0 / 1, stored as `st.w = [[kind, gx, gz, rot], ...]` in fine cells RELATIVE TO THE CORE (terrain differs per landing; offsets persist). Wall = solid collider + flow cost 25 + 260 hp; Gate = two posts + lintel, open middle, flow cost 6, 160 hp. Cost 14 / 40 credits, sell 50 %, cap `12 + 6 x zone level`, power +0.5 / +1.2 (max 10). Instanced view (body + crew-colour caps), static colliders on EVERY peer (`kind: 'znwall'`).
- **Placement** = where the player looks (button in the panel: PLACE / x4 / GATE / LINE, or `znreq {op:'wall'}` with the aim point): the host snaps to the grid and validates (`validateWall`): inside the zone ring and off the core, off other cores, off the ship + door lane, inside the map, no water, slope <= 0.9 m along the piece and <= 0.9 cross, no rock / tree (outdoor `harvest` circles), no deployable, no overlapping piece (L joints allowed), no static collider in the physics world (own wall colliders excluded), nobody standing in it, slots left. Only valid pieces of a line are charged.
- **Persistence**: at every landing `fitWalls` keeps the stored pieces that still fit the new terrain (the rest are skipped for that landing, never forgotten); the host publishes the valid list (`znx wl`, on change and every 8 s), breached pieces (`znx wbr`) are repaired for the next fight.
- **Ring defences** (turrets, barricades, spikes, mines, ...) no longer go through `debugPlace` unchecked: `ringSpots` proposes the v1 spiral first, then 17 wider / rotated retries; `checkSpot` (ship, door lane, cores, water, slope, rocks / trees, other defences, walls) + `deployables.validate` (its own slope / static / cap rules) must pass before `debugPlace`. A build with no valid spot is refused, nothing is charged, the zone is put back (same for a wing with no corridor left).

## 3. Zone economy
- **Extractor** (miner): optional, one per zone, quota 2+. homeworld2 rules reused (`MK_SPEED` 1 / 1.5 / 2.2, `MK_COST` 1 / 1.9 / 3.6, node purity impure / normal / pure = x0.5 / 1 / 1.6, seeded per run + moon + zone). Base cost 220, upkeep 3 + 2 x Mk, sell 50 %. Adds `(6 + 4 x tier) x purity x speed` credits per day INSIDE the daily cap (the cap is unchanged: 25 % of the quota) and 1 (Mk3: 2) biome material per day; each extractor raises the daily material cap by 2 (max 12). A small rig with a spinning drill stands next to the relay. A Mk2 extractor pays back in 5-60 days depending on tier / purity when the cap is not binding (tested): it is a material / late-game upgrade, not a way around the cap.
- **Archive** (`zn.arch`, saved with the run): every owned generated-sector moon is recorded compactly (`{n, t, b, s, ms, q}` = name, tier, biome, size, map scale, sector). After the sector rotates (or the moon goes stale) `moonDef` answers with the archived stub: same `zoneSpec` and income as the real moon (tested), the zones stay owned, keep paying (still capped), can be targeted by the Algorithm (auto-resolve), and show as "archived" on the map; they cannot be landed on. Records of moons nobody owns are pruned; at most 24 (oldest dropped).

## 4. Live defence: pathing + upkeep ammo
- **Raiders path around barricades**: `coreFlow` = the siege `FlowField` with the goal set to the zone core; blockers = `deployables.blockers()` + wall pieces (gate openings keep their own low cost even between two walls on the coarse 2 m grid). `moveRaider` slides along a wall when a real part of the heading runs along it, and reports a head-on block (then the raider attacks the blocker: wall hp, deployable, or a breach). Tested: a wall line and a single barricade are walked round (detour 9 m), a closed ring with one gate is entered through the gate, a fully closed ring is chewed through. Host test: no raider ever stands inside a wall piece.
- **Upkeep ammo**: paying the day's upkeep buys ammo: `payUpkeep` returns a fraction per zone (`st.am`: 1 = paid in full, unpaid zones get what is left, max 0.5, funds are not spent on them). At every landing turrets / tesla / dome / floodlight are rebuilt with `res = cap x am` (dry = empty); in a live defence a zone has `4 + 2 x level + min(6, defences)` x am refills (`L.ammo`) and every 6 s the first low (< 30 %) ammo-user gets +50 %.

## 5. Ship CRT
The vitals monitor (`shipScreens.extra`) alternates every 6 s between crew vitals and the SECTOR MAP page when the crew owns / lost a zone: `drawSectorMap` (the same renderer as the panel canvas, scaled to 96 px) for the targeted / current / richest moon, held zones, income + cap, THREAT lines, infected count, scanlines. It wraps `drawExtra` on the instance (lore.js wraps it the same way) and restores on dispose.

## Net (extends prefix `zn`)
`znreq` ops added: `wall` {z, wx, wz, fy, n, gate}, `wsell`, `mine`, `msell`. `znx` kinds added: `tp` (trap lanes), `ts` (trap states), `wl` (valid wall pieces per zone), `wbr` (breached piece); `st` cores now carry `[id, x, y, z, in, wing]`. State additions inside `run.zn`: `st.w`, `st.mn`, `st.am`, `zn.arch`.

## Knobs
`zones_core.js`: `WALL` (grid, size, cost, hp, cap, power, slope, reach), `MINER`, trap defence table (`TRAP_POWER`, `TRAP_MINQ`, cost factor 2.2), `payUpkeep` fraction; `zones2_core.js`: `ARCH_MAX`, wing core rules (`partitionWings`), trap spacing (`validateTrap`), `ringSpots` tries; `zones2.js`: `ammoReserve`, ammo tick 6 s, CRT page 6 s, wl / tp resend 8 s.

## Known gaps
- Never hand-played. One short headless run was attempted (see the report); trap lane visuals in a real facility, wall look, relay pillar inside corridors, panel layout with the new rows at 1280x720 and the CRT page are unverified by eye.
- Wall placement is "where you look" with a button, not a ghost / drag mode; corners are L joints (a 0.25 m notch), not mitred. A wall-bound raider that is boxed in behind two walls only chews (no wall-jump).
- Interior raiders follow the cell flow only (no dodging of each other, players in a doorway are attacked when within reach); they do not damage traps. Traps do not hurt players or pets by design.
- Zones on generated sectors keep paying forever while owned (capped, and bounded by `maxOwned`); there is no decay. The archive only stores the moon fields the income needs, not the defence layout (counts live in `st.d` anyway).
- Facility layouts whose key-free area is tiny (some mansions) fall back to the v1 outdoor annex relay for that wing.
- `defense_core.js` (unify) is not used; when it lands, `placeRing` / `raiderStep` are the two functions to point at it.
