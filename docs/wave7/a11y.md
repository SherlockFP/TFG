# Accessibility (wave 7, module `a11y`)

Settings > **Accessibility** tab (new) + Controls tab rewrite. EN / TR / RU (`src/game/a11y_i18n.js`, only fills gaps in existing tables).

## What
| Feature | How |
|---|---|
| Colour-blind modes (Off, Protanopia, Deuteranopia, Tritanopia, High contrast) | Not a filter. `src/core/a11y_core.js` has a palette table per mode for every signal colour (`SIGNAL_KEYS`): the 6 tier colours, HUD danger / ok / warn, trap laser / laser dim, creature eye, aimtell laser, 6 zone owner colours. `sig(key)` returns the active colour. `game/a11y.js applyA11ySettings` recolours `TIERS[id].color/hex` in place (tiers.js consumers follow), sets css `--bad --good --t-bad --t-good --t-warn`. Trap lasers (`horror_traps.js`), creature eye (`entities/creatures.js`), turret eye (`models/deployables.js`), aimtell (retints live via `onCbMode`), zone owners (`zones_core.crewColor`) call `sig`/`sigHex`. High contrast also adds `html.a11y-contrast` (white text, solid borders). |
| Keybindings | Every action in `DEFAULT_KEYS` is rebindable and listed in `KEY_GROUPS` (Movement / Actions / Hotbar and panels / Social). New actions: `reload`, `emoteWheel` (B), `daily` (F2), `roleSkill1/2`, `hotbar1-4`, `inventory`, `skillTree`, `record`, `pets`, `magicWheel`, `radio` (+ existing `sneak`). Hard-coded key sites were switched to `input.pressed('<action>')` or `game.settings.keys.<action> \|\| default`. Glitch exploits and zone beacons use `interact`, so they follow it. `bindKey()` swaps with the current owner (never creates a new conflict), refuses Esc/F5/F11/F12, warns when the key is used by a non-rebindable feature (`HARDCODED_KEYS`). Conflicts already present (old saves) show a red banner + red rows. "Reset keys" restores defaults. |
| Gamepad play | `src/core/gamepad_core.js` (pure table + `padStep`), polled by `Input.pollPad(dt)` in the main loop before `game.update`. Left stick = move (with hysteresis), right stick = look (squared response, speed slider), buttons press the key their action is bound to via a synthetic key event (so rebinds, hold-to-toggle and hard-coded key listeners all work). A jump, B crouch, X interact, Y reload/rotate, LB/RB role skills, LT scan/block (RMB), RT use/grab (LMB), L3 sprint, R3 emote wheel (hold), D-pad up flashlight / down ping / left-right hotbar prev-next (in the emote wheel: page / favourite), View inventory, Menu pause (ui.js). Menus keep ui.js `pollPad` (D-pad / A / B / LB-RB). Focus rings: 3 px outline always, bold white ring while the pad is the active device. HUD interact prompt shows `[E]` / `[Square]` etc. (`p-main[data-k]`), switches to key names when a real key is pressed. Glyph set: auto (sniffs Gamepad.id) / Xbox / PlayStation. |
| Other | UI scale slider 0.8-1.5 (css `zoom` on `#ui`), hold-to-toggle for sprint / crouch / aim (RMB block) (`settings.toggleHold`, `Input.toggled`), screen shake 0-100 % (`engine.shake/hurt` + ambient shakes), Reduce flashing lights (`engine.flash` capped at 0.22 and max 3/s, Algorithm glitch shader flicker 5x slower), FOV slider now 60-110 with a comfort hint, `loadSettings` range-checks fov / uiScale / shakeScale / padLook / cbMode. |

## Settings keys (save.js)
`cbMode, uiScale, toggleHold{sprint,crouch,aim}, shakeScale, reduceFlash, padEnabled, padLook, padGlyphs`, plus the new `keys.*`.

## Test
- `node tools/sim/a11y.test.mjs`: every mode defines every signal key; `off` equals the shipped colours; under the simulated deficiency (Machado matrices, CIE Lab distance) tiers >= 14 dE apart, zones >= 14, danger/ok/warn >= 22; keybind conflicts / swap / reserved / hard-coded warning / defaults / every action listed once; gamepad table (unique buttons, valid actions, glyphs, stick hysteresis, deadzone, wheel context); fov / flash gate.
- `tools/harness/wave7_a11y.js` (headless): palette apply, fake pad -> key state, toggle sprint, conflict banner, Accessibility tab.

## Known gaps
- Colours already drawn (loot beams, inventory tiles, spawned zone markers) update on next spawn / reopen, not instantly. Creature models with their own baked red eyes (skeletons, `combat_wave2`, most creature meshes) are not remapped; only the shared threat sites above.
- Pad buttons are a fixed table (glyph style is selectable, buttons are not rebindable). No drop / throw on the pad.
- The first capture of the mouse still needs a click (A/X tries `requestPointerLock`, browsers may refuse without user activation).
- UI scale uses css `zoom` (Chrome/Edge/Firefox 126+); fixed-pixel popups placed by `getBoundingClientRect` may be slightly off when scaled.
- Ship alarm strobes and nav-light blinks are not touched by "Reduce flashing lights" (they are slow, < 1.7 Hz).
