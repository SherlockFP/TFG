## Bounded change

Night warnings now describe danger and a waiting ship. Greed objectives retain the remaining salvage and deep-room distance without a fictional departure time. A real `departure38.seconds` request supplies the objective countdown. Manual and phase-help text explain the existing eight-second boarding warning. EN/TR/RU retain the same meaning.

An admitted native core pickup or scan label preserves price/rarity and explains the choice: install it for the next journey or sell it toward quota. The annotation changes no item identity, selection, range or LOS. Zero-value spent cores do not advertise usable fuel. A fuel objective appears aboard when usable native core custody is known, or during orbit/HQ recovery. A fresh landing without a core still teaches the airlock and facility entrance first. A known living crewmate holding a core aboard is counted; an unknown holder cannot fabricate that cue.

HQ uses the existing engine-room socket and `reactor38` receipt. Remove the spent core first. With the socket empty and fuel spent, **Company emergency refuel — ▮60** admits one virtual installed flight charge per current HQ visit. It costs up to60 existing team credits immediately; any unpaid portion is saved as `reactor38.serviceDebt`. No fresh sellable item is granted. Removing the emergency core produces native spent cargo with value0; a recovered positive core can still be installed normally or voluntarily sold. Refuel remains available at credit0 and at the finite safe-integer balance limit; an arbitrary debt cap does not strand the crew again.

Admission requires host authority, a known connected living crew member, current HQ/company phase and map seed, native standing ship-floor proof, socket range/LOS and the current token/revision. The service identity, balance and ready charge are reserved before synchronous run delivery. Replayed or stale requests cannot buy another charge; save/reload and promotion retain the service receipt. Deliberately removing a service charge on the same HQ visit requires a recovered core or a new HQ visit for another service, with a contextual socket explanation.

The native `hostSell` delayed payout emits a bounded receipt before credit addition. Only this positive salvage-credit path pays the fuel balance. The full actual sale still increments `run.sold`, XP and quota normally; the wallet receives the remainder. The existing sale result includes `credit` and `fuelPaid`, so the sale UI can show the actual deposit. Generic result replay, survey income and other wallet owners do not repay the service balance. There is no second wallet or permanent balance meter; the socket explains any outstanding fuel charge.
