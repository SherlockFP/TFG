# Wave 17: optional outdoor field work

Existing `installExpedition13` owns all four seeded job kinds. No new installer or game.js edits. On ordinary quota 1+ moons, a new landing uses seed modulo four: 0 outdoor signal, 1 existing relay vault (signal fallback), 2 survey recovery, 3 quiet uplink. `missions14.reserved` still wins; all existing moon exclusions remain. An existing token-matching saved `vault`/`signal` retains its original kind. New jobs use actual terrain path samples with existing blocked/solid checks, not arbitrary coordinates. Unsupported terrain falls back to existing jobs. Existing valid wave17 positions remain unchanged. When the legacy three-beacon plan fails, uplink now requires only its one safe station; repair requires a safe station and a distinct fuse site at least seven metres away. The fallback checks at most nine midpoint station samples and 64 fuse samples with the same 14-metre ship exclusion, solid/blocked terrain and hook/lava rejection. It does not modify the legacy signal plan. Actual generated Hamsi seed1235 now supports uplink at [22.5173,2.2654,-1.3714], rather than rejecting it for an unused early beacon.

Survey recovery: explicitly accept at the damaged drone's console; one `e17_fuse` native tool appears on an amber supply tray along the same path (`plan.fusePos`). Carry it in your hands or bag, install at the drone, then keep a live crew member within four metres with clear static/door sight for 24 active seconds. Host checks exact recorded item ID, type, holder, `state==='held'` (including an owned bag slot) before the native `it:rm` event. A 35-credit helper is optional only after installation, repairs autonomously in 32 active field seconds (slower than 24 seconds of manual attendance), freeing crew to explore. Nearby physical threats pause it. It cannot fetch the fuse, collect loot, or progress in orbit/offline. Existing scout robot/report exclusion and reciprocal i13req guard remain.

Quiet uplink: accept at the path antenna; accumulate 18 seconds with live crew presence within four metres and clear sight. Within ten metres, footsteps must be <= .14 and voice <= .12. Actual creature noise emissions above .14 near the station pause progress for 1.5 seconds, covering stationary weapons/impacts as well as movement. Leaving, blocked sight, noise, or a live creature within eight metres pauses without losing earned progress. Neither challenge starts a deadline, enemy spawn, compulsory objective or new wallet.

Completion allows one `robot` native physical salvage item, value 85 (repair) or 75 (uplink). Claim requires the same host proximity/LOS checks. Failed spawns can be retried; successful claims and repeated accepts/install requests cannot duplicate items or cash. The parcel must be carried/extracted/sold through the existing ledger. Orbit clears job state/geometry and releases helper exclusivity; it does not delete legitimately collected native items.

Console colour changes amber -> blue (accepted) -> green (complete), using one owned/disposed material. Normal objectives show progress; uplink console retains a contextual quiet/presence prompt. Completion sends existing e13fx, a beep/toast, and `mods.emit('tfg:fieldJob',{kind,stage:'complete',token},game)` on receiving peers. API remains `game.expedition13.state()/plan()`; new `progress()` returns a separate read-only summary `{kind,seconds,total,done}`. Control requests remain `e13req` with landing token and `accept/install/robot/parcel`; peers never advance or mutate state locally.

Tests: `node tools/harness/expedition17.test.mjs` and `expedition13.test.mjs` pass. Coverage includes acceptance/spawn retry, LOS, wrong/old token and wrong holder, bag-held installation, world-state denial, native ItemManager rm inventory/held callbacks, peer-operated installation, one charge/reward, large-delta clamp, quiet footsteps/voice/emitted sounds, manual absence/phase/threat pauses, autonomous helper continuing while crew leave, current-map reload, client authority, q0 exclusion, saved signal compatibility, actual generated Hamsi1235 safe station/fuse separation, and blocked/solid/hook/lava/ship-near rejection. Geometry stays merged and bounded; one fuse model is registered for warm when eligible.

Shared browser QA separately passed actual fuse pickup/installation, native repair progress and peer collection of exact item `i1xb`/85, plus actual1235 uplink/quiet completion and exact item `i3z6`/75 on both peers. Sprint noise0.275 was observed; the coarse snapshot does not establish a precise pause duration. See PLAYTEST.md for labelled setup and earlier failures. Paid autonomous help has module coverage but was not browser-tested.

Limits: module/terrain fixtures and local browser proof do not measure human fun. Peer noise uses existing replicated body/voice values; a malicious client can under-report those values just as in baseline stealth. A deleted/lost physical fuse does not silently respawn or recover on its own. Cross-session native IDs follow the existing map/item restoration rules; this change does not create an alternate item persistence system.
