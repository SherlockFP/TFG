# Wave 5 - zfixperf: invisible zombies, GPU leak sweep, outdoor prop merge

## 1. Zombies sometimes invisible (fixed, browser-verified)
Root cause candidates found in `SwarmRenderer` (src/models/creatures_wave1.js): (a) it was advanced ONLY by `horde.js` update, so any session where the horde module is off / disposed / gated drew nothing while zombots still existed (`SWARM.dispose()` also cleared every record); (b) it attached to the first record's `root.parent`; (c) a hard cap of 48 bodies dropped arbitrary extras (dice swarm, sieges, dev spawns). Every space (mirror, pockets at x>=6400/8000, homeworld) shares the ONE game scene, so no per-space fallback model is needed.
- `CreatureManager.update` (src/entities/creatures.js) now calls `SWARM.update(dt, this.scene, camera.position)` every frame on host AND clients; the horde module's own call is deduped (2 ms guard).
- Always attaches to the scene it is given (re-adds the meshes if something removed them), rebuilds after `dispose()` (records survive, leftovers of an old session's scene are pruned), respects `root.visible`, cap 72 and keeps the NEAREST bodies when exceeded.
- New instanced poses: `crawl` (legs trail, low body, arms haul; 12% born as crawlers, any zombot under 35% hp becomes one at half speed), `grab` (35% of melee attempts: lunge, arms clasp, same timing/damage as `attack`), `getup` (0.9 s after a stun: plays the fall backwards). Behaviour glue in src/game/creatures_wave1.js (`zombotBehavior`); states are plain strings in snapshots, no net change.
- Headless verification (tools/harness/wave5_zfixperf.js, screenshot checked): outdoors 8 spawned -> 17 instanced bodies attached to `engine.scene`, 8 inside the frustum, still 17 after `game.horde.dispose()` (client-like); indoors (facility) 5 spawned -> 9 bodies drawn. Backrooms pocket step did not run (time budget) - same scene, so expected fine. No page errors.
- Node: `node tools/harness/zfixperf.test.mjs` (25 checks: attach, nested parents, dedupe, all poses finite, crawl lower than run, cap = nearest, dispose/re-init, stale-scene prune).

## 2. GPU geometry leak (best-effort fix, NOT verified in a browser)
`renderer.info.memory.geometries` is only decremented by `geometry.dispose()`. Meshes that modules remove from the scene without disposing (per-instance creature/item model geometry, instanced props: `terrain.dispose` skips `InstancedMesh`, ...) stay counted. A headless diagnostic (tools/harness/wave5_zfixperf_leak.js) tracked 33 such geometries after ONE landing (items.js:174 x15, creatures.js model parts x11, geobuilder.js:290 x3, inventory.js:587 x2, survival/extmodels x1 each), and 437 vs 248 base geometries after takeoff.
Fix: new module `src/game/gpusweep.js` (`useModule('gpusweep')`): while a map is loaded it remembers every geometry/texture in the scene (1.5 s scan); 2.5 s after the map is gone, everything remembered that is no longer reachable from the scene is `dispose()`d (only frees the GPU copy; shared/cached resources just re-upload; render-target/video textures and `userData.shared` geometries are skipped). `game.gpusweep.stats()`.
CAVEAT: the same-moon 3-cycle run (wave5_zfixperf.js) showed 567 -> 575 geometries but the sweep never fired (`sweeps: 0`): landing the SAME moon+seed again keeps the map loaded (game.js `loadMapFor` early return) and the harness `takeoff()` apparently did not reach `orbit`, so it was not a real reload test. The follow-up run (tools/harness/wave5_zfixperf_plateau.js, 2 alternating moons x2, prints phase/moonId/geos/sweep stats per cycle) was cancelled at the lead's request. QA: run it and check `postSweep.geos` plateaus and `sweep.sweeps > 0`.

## 3. Draw calls (partial)
`terrain.js`: plain decorative props (POI junk, landmarks, lamp posts, pond reeds) now go through the existing `mergeStaticMeshes` (24 m cells, per material) at the end of the outdoor build; props whose subtree carries any userData other than colliders/lights/propId/size/mount (animated parts, anchors) are skipped; outposts/entrance/fire exits untouched. Kill switch `globalThis.__kefalNoOutMerge = true`. Measured on hamsi: outdoor 556 calls (merge off) vs 573 (on) - no measurable gain on that moon (props there are mostly instanced already); the Sector Core / mirror / landed-ship numbers were NOT measured. Not done: ship and mirror prop merging.
