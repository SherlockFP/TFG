# Wave 2 — Localization (EN / TR / RU)

Owner request: "make localization complete — sometimes not everything turns Turkish; add Russian too".
Languages: **en** (source text), **tr**, **ru**. Picker: title screen buttons `EN TR RU` and Settings > Gameplay > Language
(`English / Türkçe / Русский`). First run: `navigator.language` `tr*` -> TR, `ru*` -> RU, else EN (`core/save.js`).

## How it works
English strings are the keys. `src/core/i18n.js`:

| API | Use |
|---|---|
| `t('Text')` | translate a literal; falls back to the English key (never to TR, so RU never shows Turkish) |
| `tf('Ship: {d} m', { d })` | translate + fill `{name}` placeholders. `{@name}` also *translates the value* (moon / item names sent by the host) |
| `L({ en, tr, ru })`, `LA([en, tr, ru])` | tiny inline tables (missing languages fall back to `en`) |
| `addTranslations(map, lang = 'tr')` | register strings at runtime; old TR-only calls keep working, pass `'ru'` for Russian |
| `sysMsg(key, vars, kind)` / `sysText(d)` | host -> clients messages every peer localises itself (see below) |
| `tIn(lang, s)`, `tfIn(lang, s, v)` | explicit-language variants (host building English text, `hasTranslation`) |
| `setLang`, `getLang`, `LANGS`, `nextLang`, `detectLang`, `speechLang`, `onLangChange` | language state; `speechLang()` = `en-US / tr-TR / ru-RU` for voice spells |
| `localizeFields(obj, fields)`, `localizeDeep(root, fields, depth)` | display-name path (below) |

Bulk dictionaries are pure data in `src/i18n/`: `tr_*.js` / `ru_*.js` (`export default { 'English': 'Translation' }`),
aggregated by `src/i18n/tr.js` / `src/i18n/ru.js` (add your file to the `*_PARTS` array). The original TR table stays in
`core/i18n.js`, modules may still call `addTranslations(...)` themselves.

Current files: `ru_core/tr_core` (UI, HUD, terminal-adjacent, items UI, facility/inventory/crafting/shop/magic tables),
`*_names` (item / creature / moon / affix / weather / weekly / modifier / market display text), `*_wrap1` (strings wrapped by
the codemod: toasts, prompts, sys messages, terminal), `*_manual` (HOW TO PLAY, voice panel, report/badges, HUD, CRT text,
ranks, suit and hat names), `*_local`, `*_local2`, `*_data2` (contracts / case files / panels / events / recipes / codex),
`ru_lore` (Algorithm voice lines, factions, contracts, chains; keyed by the English half of the old `[EN, TR]` pairs),
`ru_ach` (achievements).

### Display names of game data (ids never change)
`src/i18n/display.js` (imported from `main.js`) turns the `name` / `tip` / `desc` / `lore` / `note` / `short` fields of the data
tables (ITEMS, CREATURES + VARIANTS + AFFIXES, MOONS, WEATHER, BIOMES, SHIP_UPGRADES, MARKET, MASTERY, WEEKLY_MODS,
moongen MODIFIERS, RECIPES, BLUEPRINTS, MILESTONES, STRANGE, EMOTES, suit / hat colours) into getters that go through `t()`.
Every existing `def.name` read site is therefore localised without edits; `def.$name` is the untranslated English text
(terminal search, network payloads, regex lookups). `registerItem` / `registerCreature` localise mod-registered defs too.
Add a new table by calling `localizeDeep(TABLE, ['name', 'desc'], depth)` in `display.js`. Do **not** call `t()` in
module-level data (it would freeze the language at import time) — use the getters or wrap at the read site.

### Host -> client text
Host code must not bake its own language into what other peers see. Use `net.broadcast('sys', sysMsg('{name} joined the crew.', { name }, 'info'))`
(client: `net.on_('sys')` -> `sysText(d)`), and terminal replies `reply('Ordered {n}x {@name}. ...', false, { n, name: def.$name })`
(`d.k` / `d.v` are localised in `Terminal.onRemote`). `text` still carries the English rendering for old clients. Use `{@x}` for
values that are display names (moon / item / creature) so the *receiver* translates them.

### Other language-specific things
- Fonts: Press Start 2P (bundled @fontsource) already has Cyrillic + Latin-ext; VT323 has no Cyrillic, so `style.css` defines
  `TFG Cyr VT` (the bundled Press Start 2P Cyrillic subset, `size-adjust: 58%`) as the fallback in `--font` and in the canvas
  stacks of `crtmenu.js` / `hud.js`. No CDN. `setLang('ru')` preloads the faces (canvas text needs loaded fonts).
- Voice spells: `magic.js` spells carry `say.ru` + `words.ru` (ТОЛКАЙ, СВЕТ, ЛЕЧИ, ТЯНИ, ТИХО, ПРЫЖОК, ЩИТ, ОГОНЬ); `magic_voice.js`
  normalises Cyrillic, `SpeechRecognition.lang = speechLang()`; The Algorithm's speech synthesis also follows `speechLang()`.
- `pickLang([en, tr])` (loredata) ignores its 2nd arg: TR from the pair, RU from the dictionary keyed by the English half.
- Panels with a local `L(en, tr)` / `L(s)` helper (contracts, casefile, record, roles, passive tree, achievements) now fall back to
  `t(en)` for RU.

## Adding strings (checklist)
1. Wrap: `t('Text')` / `tf('Text {x}', { x })` (placeholders `{x}`, glyphs `▮ ◈` and `[E]`-style tokens must survive translation).
2. Add TR + RU to a `src/i18n/tr_<area>.js` / `ru_<area>.js` file (register it in `tr.js` / `ru.js`), or `addTranslations(map)` / `addTranslations(map, 'ru')`.
3. `node tools/i18n_audit.mjs` — must show 0 missing TR / RU for your files.
4. Host-sent text: `sysMsg` / keyed `reply`, never a pre-formatted string in the host's language.
5. Data tables: add the table to `src/i18n/display.js`; keep ids and English text as the source of truth.
Tone: dead-internet humour (docs/THEME.md); TR informal "sen"; RU informal "ты", internet slang where the joke needs it
(клаут, слоп, тикет, реплай-гай). Proper nouns stay Latin (TFG, Phish Dayı, 0-Algorithm HQ, moon names).

## Tools
- `node tools/i18n_audit.mjs [--verbose] [--file <substr>] [--only missing|unwrapped] [--max N] [--all] [--json] [--dump]`
  static (AST) scan: keys used via `t()/tf()/sysMsg()` vs TR and RU dictionaries (inline `addTranslations`, `src/i18n/*`, the core
  TR table), `{en,tr}` / `L()` / `[en,tr]` / `A()` local tables missing RU, and likely user-visible hard-coded strings per file
  (toast / print / systemMessage / label / sub / name / desc / textContent / innerHTML text). `--dump` prints JSON of every key still
  needing RU (with its TR text) for bulk translation. Re-run it after merging other branches.
- `node tools/i18n_wrap.mjs [--apply] [--keys out.json] <files>` — codemod used for this pass: wraps toast / prompt / sys / print / label
  strings (template literals and `+` chains become `tf()` keys, `sys` payloads become `sysMsg()`), skips module-level and shadowed
  `t`/`tf` (uses `_t` / `_tf` aliases), prints the key list to translate. Review the diff; expressions inside `${}` are copied verbatim.
