# Wave 5 - ZONES (module `zones`; MASTERPLAN §26 v1; node-tested + builds, NOT run in a browser: the one headless attempt timed out on the shared lock)

The owner's new core direction: extraction stays as it is, and on top of it the crew reclaims moons zone by zone (capture, fortify, passive income, counter-attacks, a sector map).
Installed with `this.useModule('zones', installZones)` (`game.zones`), off with `config.zones = false`.

## Files
- `src/game/zones_core.js` pure rules (partition, core placement, capture / build rules, income cap, upkeep, auto-resolve, attack picking, terrain reach). Node-tested.
- `src/game/zones.js` module: host runtime + net + 3D views + terminal + interactables. `src/game/zones_i18n.js` TR + RU. `src/ui/panels/zones.js` the sector-map panel (ui2 base classes).
- Tests: `node tools/harness/zones.test.mjs` (1088 checks: determinism, reachability of every core on real terrain of 30 moons, rules, cap maths, odds, upkeep) and `node tools/harness/zones_host.test.mjs` (mock-game host flows, 28 checks). Browser script: `tools/harness/wave5_zones.js` (not run).

## Design
1. **Partition.** `zoneSpec(moon, runKey)` (seeded by `runId + moon.id`, works for charted, generated-sector and voyage moons) gives 3-6 zones: open sectors around the ship (A = safe, ~40 m out, always open) plus facility wings anchored on the entrance ("Main Hall") and the fire exits ("East / West Annex"). Threat = moon tier + rank/2 (+0.5 for wings). Later zones unlock by quota (rank 2-3 from quota 2, rank 4-5 from quota 3). Company HQ, homeworld, instances / cycle / gate moons have no zones.
2. **Cores.** Terrain differs per landing (`run.seed` is re-rolled), so the host places the cores at landing time on the real terrain (`placeCores` + `coreProbe`: dry, gentle slope, flood-fill reachable from the ship, clear of ponds / lakes / flats / entrance / other cores) and sends them to clients in the 1 Hz `znx` state. Zone identity (A..F, kind, threat) is stable; only the exact spot moves. Facility wings are outdoor "annex relays" next to the entrance / exits (interior placement is a later step).
3. **Capture.** No hostile creature within 28 m of the core for 20 s (timer runs while a player is within 45 m), stand at the core, press E: the host runs a 4 s plant (cancels if you leave, a hostile shows up or credits run out). Cost = 35 + 20 x tier + 12 x rank + 10 x zones held (first beacon on a tier-1 moon = 55, affordable with the 60 start credits; recapture of an infected zone half price). Limit `maxOwned = min(12, 3 + 2 x quotaIndex)`. Owned: emissive crew-colour pillar + a faint ground ring (24 m, terrain-following ribbon), infected: flickering red. No lights added.
4. **Fortify.** Owned zone console (E at the core) or `ZONES`: the panel's FORTIFY list builds defences from the EXISTING deployables (`game.deployables.debugPlace`: wood / metal barricade, spike strip, mine, turret MK1-3, tesla, floodlight, shield dome) around the core, costs credits (no kit needed), slots 6 + 2 per zone level (level 0-3, upgrade 160 / 320 / 560), sell = 50 % refund. Defences are stored abstractly in `run.zn` and re-materialised as real deployables each landing (they vanish on take-off anyway). Upkeep per defence per day (2-12 credits); unpaid upkeep = zone "dry" (defence power x0.4, turrets start empty).
5. **Income.** Per day per owned zone: `(10 + 7 x tier) x (1 + 0.15 x rank) x (1 + 0.25 x level)` credits + 1-2 biome material (dropped in the ship). Total is hard-capped at `max(20, 25 % of the quota)` per day (materials 4/day), then upkeep is paid from it. Offline / away catch-up (homeworld2 style, `offlineDays`): >= 15 min real time away = 1 day per 30 min, max 3, at 50 % of the capped rate.
6. **Counter-attack.** At every day end (`hostFinishTakeoff` wrapper) the Algorithm votes 1-2 owned zones (never before quotaIndex 1 = quota 2; 2 only with >= 4 zones). The vote is announced (intercom line + THREAT objective) so the crew may fly there. Crew on that moon at dusk (17:00) -> LIVE defence: 2 waves from siege_core (`siegePower` + `planWave`, same sg_* creatures), raiders go for players, your deployables, then the core (300 HP + 100 per level); waves cleared = zone held with 1.5x bonus, core dead = infected. Otherwise the next day tick AUTO-RESOLVES: defence power vs wave power (`(10 + 9 x threat) x (1 + 0.1 x quotaIndex) x crew factor`, x0.75-1.3 seeded jitter; solo x0.75). Win = credits + material, lose = zone infected (no income until recaptured, half the defences lost). Intercom lines EN / TR / RU ("The viewers voted for Sector B on ...").
7. **Sector map.** Terminal `ZONES` (prints a summary, `ZONES TEXT` only prints) opens the panel: moons -> zones with owner / income / threat / defence power, a top-down minimap per moon (live core positions on the current moon, schematic otherwise), zone detail with odds vs the next wave and the build menu.

## Net / state
`znreq` (client -> host `{op: plant|build|sell|up}`), `znx` (host -> all: `st` 1 Hz cores + clear timers + planting, `plant`, `deny`, `taken`, `banner`, `live`, `algo`), `znx` is in `HOST_ONLY`. State `run.zn = { m: {moon: {zoneId: {s: 'own'|'inf', d: {def: n}, up, dry, since}}}, col, pend: [{m, z, d}], rt, day, rep, stat }` (synced with `broadcastRun(['zn'])`, saved with the run, reset with a fired run). Host profile: `profile.zn = { captured, held, lost }` lifetime counters.

## Knobs
`ZN` (radii, timers, slots, upgrade costs, income cap, offline, wave jitter, dusk), `DEFS` (cost / upkeep / power / unlock quota), `maxOwned`, `captureCost`, `zoneIncome`, `wavePowerMean`, `crewFactor` in `zones_core.js`.

## v1 vs later
v1 (done): everything above. Later: facility-interior wings (cores inside the facility layout, horror traps as wing defences, homeworld2 wall pieces - only outdoor deployables are wired), miners / extractors per zone (homeworld2 factory logic), zone-specific events, a ship CRT map (terminal + panel only now), zones on generated sectors are dormant once the sector rotates, cross-quota zone persistence for dark sectors, live raiders ignore barricade collision (straight-line movement, no flow field), balance pass with real play (income cap / attack odds are paper numbers), profile-level meta (profile.zn is only counters), NPC-style crew colours picker.

## Known gaps
Never looked at in a browser (pillar / ring look, panel layout at 1280x720, interact prompts). The headless run timed out waiting for the shared browser lock. Deployables placed through `debugPlace` skip the placement validation (slope / overlap), so a ring position on a rock can clip. i18n audit lists the module's strings as missing because they are registered through a filtered `addTranslations` (false positives, same as voyage).
