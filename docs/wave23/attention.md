# Wave23 — local lift attention

Audit found three independent presentation paths during native depth travel: the long lift control explanation, a depth/tier/rule toast immediately after rebuilding, and ordinary queued Algorithm/tutorial/achievement/arrival messages draining because travel is not combat. The existing cabin signs and physical action prompts already describe the lift. No new panel is needed.

`descent21.presentationBusy()` now identifies a living local player inside the actual cabin during calling/travelling, or for at most four game-clock seconds after a floor change. Leaving the cabin releases it immediately. The initial surface spawn, an ordinary room, a dead player or an inactive map does not qualify. This API changes presentation only; authority, floor state, transit duration, custody, discovery and spawn budgets are untouched.

The shared `routineAttentionBusy` predicate combines this presentation window with existing real threat pressure. `attentionHot` remains unchanged, including Warden owner checks. Native HUD toast/banner queues, Algorithm queue, tutorial speech, achievement queue, landing sequence and soul cards defer their ordinary content through their existing mechanisms. Optional goal rows wait briefly; warning rows and physical interaction prompts remain. Warning toast capacity remains normal during safe travel, and actual danger still uses its own one-warning policy and CSS. A depth/rule toast is ordinary information, so it waits rather than bypassing threats or menus. A subsequent floor change removes only the prior depth notice from the existing pending queues; it does not grow another message ledger.

Validation extends existing fixtures. Native generated-facility travel checks the installed API during actual accepted descent, four-second expiry, immediate cabin exit and unchanged noncombat predicate. The real HUD queue fixture verifies unread depth information and optional rewards wait while rescue warnings pass and the same notice releases. Installed Algorithm coverage verifies an urgent line can pass a deferred teaching line and teaching resumes after leaving. Existing danger, center-card, unchanged-frame HUD-write, soul, Algorithm context and landing sequence checks pass. Browser screenshots and native shared-context QA are separate evidence owned by the QA agent.

A separate prior combat flag also detects genuine danger beginning inside an already quiet arrival: two visible safe warnings become one visible plus one queued, and both return at safe capacity afterward. The installed HUD regression exercises this transition through native update/toast/queue methods.
