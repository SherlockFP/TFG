# wave8 perf6 - landing WARM SET (first-use hitches) + perfInfo

perf4/perf5 left the first-use hitch: `landQ.prewarm` (`renderer.compileAsync`) covers only what is in the scene at that moment, so the first creature, scrap piece or VFX compiled its shader / uploaded its textures during play.

## What was built
- `src/game/warmset_core.js` (pure): `warmPlan(run, moon, theme, deps)` -> `{ creatures, items }`. Creatures: `poolFor` residents + theme creature first, then the moon's `spawnTable` in/out by weight; one per model key, cap 12; `mimicdoor/web/company/kefaldayi` skipped. Items: top 20 of `scrapTableFor(theme)` + top 8 of `bigTableFor(theme)` (hero / repo / labyrinth themes are covered because they fill those tables), only ids that have a model builder.
- `src/game/warmset.js` (`game.warmSet`): `queue(q, run, moon)` is called from `loadMapFor` right before `q.add('prewarm')`. Job `warm:plan` (runs after the facility + all mapLoaded jobs exist, so the theme is real) uses `q.addNext` to add `warm:vfx`, `warm:c:<id>`, `warm:i:<id>`: one small job each (a few ms, well inside the 8 ms per frame budget and the 9 s descent). Each builds the model with the same path as `CreatureView` / `WorldItem` (mod model maps first, then `createCreatureModel` / `createItemModel`), parents it under a hidden group at y = -4000 (visible, so the compile traverse sees it) and calls `renderer.initTexture` for its maps.
- VFX set (`vfxObjects`): floor-cone (vertexColors rgba additive, polygon offset), drone beam cone / eyes (additive, fog false), disc / downed ring, web-label plane (map, fog), tell mark (toneMapped false), feedcams junction boxes + camera body (Lambert vertexColors, instanced) + lamp (instanced Basic with instance colour), muzzle sprite (additive SpriteMaterial + canvas map) and carry strap (LineBasicMaterial). Same program parameters as the real ones (three keys programs by parameters). Other modules may `game.mods.on('warm', (reg) => reg(objectOrTexture))`; `feel.js` uses it to upload the real muzzle-flash texture.
- `landingq.js`: `q.afterPrewarm` callbacks run when `compileAsync` resolves (or immediately without a renderer / on error) and on `clear()`; the warm group is removed there. Materials are NOT disposed on purpose: disposing them releases the compiled programs (three ref-counts programs per material); only unshared geometry is disposed.
- DOM-only pops (reward pop, downed ring / revive UI, HUD) are CSS, not GPU shaders, so nothing to warm.
- `kefal.game.perfInfo()`: `{ programs, programNames (name -> count), geometries, textures, calls, triangles, warm: { built, models, ms, programsBefore, programsAfter, plan } }` from `renderer.info`. Read it after a landing (before / after: `programsBefore` is taken when `warm:plan` runs, `programsAfter` when the group is removed). Kill switch: `kefal.game.warmSetEnabled = false`.

## Material dedupe (task 2): audited, nothing to merge
three builds a program per program cache KEY (material type + define set: map / vertexColors / flatShading / fog / side / instancing / toneMapped ...), not per material instance; a hundred `MeshBasicMaterial({color})` share one program. Audit: `models/items.js`, `models/artpass.js` and the creature models already go through the `getMaterial` / `getBasicMaterial` caches; `crdirector` eyes and `creature_read` tell marks are cached per colour; `lcmonsters_models` makes per-instance Lambert (flatShading) / Basic materials but they all hash to the same 2 programs; feedcams / feedcams2 create a handful per build (drone beam / disc materials are per drone because the colour is mutated per frame; still one program each). Merging them would cut JS allocation, not programs, and risks shared-colour bugs, so no code was changed. What multiplies programs is parameter variety, which the warm set now compiles ahead of time.
